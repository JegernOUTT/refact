Review the current change set. First establish its intended behavior and acceptance criteria. Use independent `subagent()` reviewers with different concrete `model_name` values against the same pinned checkout, diff and criteria. Select relevant domains: diff-only correctness on both sides of each changed boundary, integration and compatibility, duplication and reuse, security/privacy, concurrency/lifecycle, spec compliance (unmet, reinterpreted, narrowed or weakened requirements, and changes no requirement needs), verification integrity (deleted, skipped, loosened or rewritten tests, mocks of the behavior under test, production code that special-cases test inputs, CI changes), test strength, and performance. Restrict tools to authorized inspection and verification; review directly if delegation is forbidden. After independent discovery, exchange findings with `agent_message()` while reviewers are running, or launch fresh challengers if they have finished, for one round aimed at disproving each claim. Adjudicate by source evidence and executed checks rather than model majority, distinguish source-backed claims from executed reproductions, preserve unresolved disputes, and report unchecked domains. List actionable issues by severity, each with location, trigger, violated contract, impact, the counterevidence checked and the smallest fix. Maintainability issues need a concrete cost, style preferences stay optional, zero findings is a valid result, and no finding rests on presumed authorship.
