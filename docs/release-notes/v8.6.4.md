# v8.6.4

v8.6.4 makes chat delivery and context reconstruction more visible and reliable, replaces review wall-clock limits with inactivity detection, corrects live model discovery for subscription providers, and hardens shared workspace state.

## Highlights

- **Reviews now time out only when they go silent** — A review stage that continues reporting activity can run past its former wall-clock budget; silent stages time out after the configured idle period instead.
- **Chat delivery is durable and visible** — Messages and runtime events are delivered through a persistent queue, with inline event rows, a compact queue above the composer, and waits that can be interrupted for pending delivery.
- **Context rebuilding is unified and explainable** — Automatic and requested rebuilds follow one active-history path, avoid premature rebuilding from an inflated estimate, and show a report of the reconstruction.
- **Subscription-provider model lists come from the provider API** — Claude Code, GitHub Copilot, Google Antigravity, OpenAI Codex, and xAI OAuth use their live model records and capabilities instead of catalog IDs and hardcoded context sizes.
- **One engine owns a workspace** — Workspace roots now take a process-lifetime lease, preventing multiple engines from writing the same normalized workspace and CodeGraph store concurrently.
- **CodeGraph parses TSX correctly** — `.tsx` files use the TSX parser and parser-generation changes force unchanged files to be parsed again.

## Behaviour changes

- **Review timeout configuration has changed.** Reviews previously applied per-stage wall-clock budgets and an overall `deadline_secs`; queued stages could become `not_run` when that deadline expired. The `deadline_secs`, `stage_budget_minutes` and `writes_stage_budget_minutes` tool and configuration fields are removed; a per-stage `budget_minutes` left in a stage yaml or a `review_agents.yaml` override is still accepted but ignored, and logs a warning saying so, so existing configuration keeps loading. A stage now stops only after no activity for `idle_timeout_secs` (default 360 seconds, minimum 30), followed by the existing 10-second soft-abort grace; parent cancellation still stops the review. Callers that relied on a total wall-clock budget must enforce that limit outside `review`, for example by cancelling the parent operation.
- **Live discovery is authoritative for five subscription providers.** For Claude Code, GitHub Copilot, Google Antigravity, OpenAI Codex, and xAI OAuth, models.dev may enrich fields only for model IDs returned by the provider API; it cannot add an ID. If live discovery is unavailable, these providers expose custom models only rather than a catalog fallback. A catalog entry alone therefore no longer makes an unreturned provider model available.
- **A workspace already served by another engine is now rejected explicitly.** Each normalized workspace root holds an advisory lease for the engine process lifetime; managed worktrees share their source workspace's lease. Opening a root whose lease is held reports that it is busy instead of silently serving a reduced folder set.

## Chat

- Message delivery now uses a durable queue that preserves pending deliveries across restart, supports append, preempt, and when-idle boundaries, deduplicates queued work, and routes runner and process-completion notifications without interrupting an active draft by default.
- Events render as compact, expandable rows in the transcript with their source, summary, timestamp, typed details, and raw payload. The separate event-history card is removed.
- The delivery queue is a dense, scrollable dock immediately above the composer. It shows queued count and live delivery status, lets you select the push mode, and expands an item inline.
- `sleep`, `agent_wait`, and `process_wait` are interruptible waits: pending append and when-idle deliveries can end the wait, return an interrupted result, and resume generation in order for both live sessions and runner subagents.
- Context reconstruction now has one owner for active history, covering automatic rebuilds, manual compression, and mode transitions. Rebuilt history carries message and token counts before and after, tokens saved, reduction, trigger, and model; the UI shows these in a collapsed Context rebuilt card.
- Automatic context rebuilding no longer combines raw byte length with its token estimate, which could rebuild a chat prematurely. A fresh provider-usage measurement now replaces the local estimate for the request it measured, and incomplete frozen request prefixes use local reconstruction instead of failing solely because a system prompt or canonical-tools shape is unavailable.
- Background agents can complete after an edit-tool response: runner closure now accepts the edit tool's `diff` result as satisfying its pending call.

## Providers

- GitHub Copilot discovery no longer filters out every model because its live records set `model_picker_enabled` false; it excludes embeddings and uses the provider policy and advertised endpoints instead.
- Claude Code reads its live `max_input_tokens` and `max_tokens` fields and maps advertised reasoning, image, PDF, structured-output, and thinking capabilities instead of applying a fixed context size.
- xAI OAuth reads the live `context_window`, Google Antigravity reads `maxTokens` and provider role signals, and OpenAI Codex uses the API visibility and API-support flags. Models without a live or catalog context window are not invented.
- Available-model data and GUI wire data now carry video, audio, PDF, minimum-thinking-budget, image, maximum-completion-token, and high-context pricing fields where supplied.

## CodeGraph and workspace state

- CodeGraph uses the TSX grammar for `.tsx`, keeps JSX and TSX language IDs distinct, and updates its tree-sitter grammars. A parser-generation mismatch clears cached hashes and parse failures so unchanged files are reparsed without dropping the database.
- CodeGraph will not delete a database with a schema newer than the engine supports. It leases the database while open and detects replacement by another process, then reopens and requeues the workspace while preserving pending work.
- Trajectory indexing uses a journal with sequence numbers and checksums plus a locked checkpoint transaction, preventing concurrent checkpointing from losing newly appended entries. Listing and lookup caches avoid repeated filesystem work while retaining invalidation for new child-directory files.
- Buddy memory operations are serialized with a cross-process file lock for every read-modify-write transaction, including compaction, repair, archive, and temporary-file cleanup. Its cache is bounded per workspace rather than being displaced by another workspace.

## Performance and fixes

- The engine excludes its own runtime state and generated data from workspace indexing, debounces file events, coalesces background-agent records, and avoids full-text-search scans and unnecessary WAL checkpoints during CodeGraph updates.
- Process observation publishes each newly seen path and read/write bit once, rather than repeatedly sorting and scanning a growing list; shell and process tools log only the observation decision and counts at debug level.
- Trajectory link-type probes use buffered reads and stop once a non-internal link type is known, avoiding a read syscall per byte when classifying large trajectory files.
- Busy workspace roots are reported to the client with distinct diagnostics for an engine-held lease and an unreadable lease, rather than appearing to have no results.
