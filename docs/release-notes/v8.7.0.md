# Refact v8.7.0

Refact v8.7.0 adds Python Code Mode, a chat-led review canvas, and project Apps
with supervised automation sources. It also expands the browser workspace,
improves agent recovery, and makes runtime selection and staging more visible.

## Highlights

- **Python Code Mode** — Agents can combine allowed tools in persistent Python
  scripts, inspect structured results, and present tables, charts, and Markdown.
- **Chat-led reviews** — A review canvas brings guided HTML Tours, diffs,
  findings, source evidence, and pull-request discussion into one workspace.
- **Project Apps and automation** — Persistent layouts and shared project Apps
  sit alongside chats, with explicitly authorized live data sources.
- **A browser-first workspace** — The CLI opens the dashboard, while responsive
  tabs, split panes, file previews, Git views, and an image editor support daily work.
- **Clearer runtime management** — Public release selection, integrity-checked
  staging, startup diagnostics, and observed versions distinguish what is selected,
  cached, and actually running.

## Python Code Mode

- The new `python` tool runs scripts in a persistent, per-chat Monty interpreter.
  Variables and helper functions can be reused across snippets; allowed tools are
  exposed as typed async functions with structured results and discoverable help.
- Scripts can await individual tools or coordinate calls with `asyncio.gather`,
  process results locally, and use `llm()` for model requests. Guarded engine
  functions expose chat, agent, provider, settings, and other engine operations.
- Nested calls retain tool authorization, approval, and hook checks. Live call
  records show their progress and results rather than treating a script as one
  opaque operation.
- The Python workspace exposes variables, run output, files, and artifacts.
  `show()` renders tables, charts, and Markdown; Script cards start collapsed,
  while explicitly requested displays remain visible below them.
- Run records and restored state preserve privacy provenance. Protected-state
  checks recognize file identities, including hard-link aliases, rather than
  relying only on path spelling.

## Reviews

- Review mode is led from chat and updates a persistent canvas as work arrives.
  Guided HTML Tours can embed native code excerpts, diffs, and evidence blocks,
  so explanations stay connected to the material being reviewed.
- Findings can carry source evidence. Review tools check
  that referenced sources belong to the current review instead of accepting an
  unrelated evidence identifier.
- Pull-request discussion can be imported and synchronized with GitHub, including
  replies and an explicit outbox for publishing comments.
- Stack-aware review context refreshes as the stack changes. Context ordering and
  the review-chat prompt prefix are kept stable to improve prompt-cache reuse.

## Project Apps and automation

- Apps integrate into the main workspace with persistent pane layouts and state.
  A project's App catalog is shared across its registered worktrees.
- Live sources support supervised refresh and lifecycle controls, with visible
  loading, permission-required, and error states. Declaring an App permission or
  action does not itself grant access or authorize arbitrary shell execution.
- Source grants bind to the published revision and the relevant file, endpoint,
  or owned process. Republishing requires grants for the new revision.
- Background tool output is attached to the originating call, and structured App
  completion events render alongside other multimodal chat events.

## Agents, goals, and recovery

- Execution plans belong to the current goal, with shared planning and pursuit
  controls. Task-planning goals wait for user approval before pursuit starts.
- Parent and planner pause controls stop agents at safe boundaries without
  interrupting an active tool. Paused and needs-attention states are visible on
  task cards instead of being confused with stalled or failed work.
- Finished agent chats are sealed against accidental generation and require an
  explicit continuation. Continuing an isolated child after its worktree was
  merged or removed creates a fresh worktree from its original merge target.
- Fresh restarts capture the previous worktree's changes before removal. Merge
  workflows respect the checkout that holds the target branch and retain
  actionable conflict and recovery information.
- Recoverable agent trouble can request attention without immediately failing the
  card. Unreadable background-agent records are isolated with diagnostics so
  healthy records can still load.
- Follow-up messages to finished children report that they are saved for an
  explicit continuation, not delivered to an active run. Stale questions and
  approvals are withdrawn when their owning run ends or is replaced.

## Search, providers, and MCP

- Web search orchestrates multiple providers, merges and ranks results, and
  supports categories, freshness, and domain filters. A dedicated settings page
  controls providers and credentials, including a configurable SearXNG endpoint.
- `manage_mcp` can list integrations, inspect status and redacted logs, reconnect,
  and save or remove project/global MCP configurations. Connection recovery and
  stale privacy-label handling reduce calls blocked by outdated state.
- LiteLLM gains account insights and managed MCP support, including canonical
  gateway handling and explicit OAuth discovery errors.
- Provider setup adds guided AWS Bedrock flows and Claude Code Console OAuth and
  native cloud sign-in options.

## Workspace and performance

- Responsive workspace tabs and split panes support chats, files, previews, and
  other content. Explorer gains indexed search, and the compact image editor can
  attach an edited image directly to chat.
- Git tooling adds commit and log views, branch actions, and editor diff tabs.
  Project chat/task organization and activity-aware status indicators make
  ongoing work easier to find.
- Compact transcript rows unify tool and agent feedback. Background-agent
  transcripts, structured questions, and the redesigned composer keep controls
  close to the conversation without opening the Agents dock automatically.
- A connected engine console and guided workspace navigation expose daemon
  activity. Live queue and first-output diagnostics help explain delays.
- Incremental project context, cheaper trajectory saves, bounded chat opening,
  multiplexed chat streams, and reduced GUI polling cut repeated work. File
  inventory updates also avoid rebuild loops and discover new directories sooner.

## Runtime and release delivery

- Runtime management selects and resolves public assets from `JegernOUTT/refact`.
  On Linux, it stages them with manifest, size, hash, and provenance checks.
  Version observations distinguish the selected, staged, daemon, and worker runtime.
- VS Code and JetBrains integrations expose startup diagnostics and observed
  runtime versions; IDE plugins remain updated through their IDEs.
- Tests, Prerelease, and Release are separate workflows, with release artifacts
  tied to their source revision and verification evidence.

## Behaviour changes and limits

- **Python is a Monty subset, not CPython.** Arbitrary third-party packages,
  native extensions, subprocesses, and networking modules are not available in
  the interpreter; use allowed tools for those operations. Direct filesystem
  access follows process permissions and protected-path rules, not a project-only
  sandbox, and can write project files even in read-only modes.
- **Tool jobs are in memory.** An engine restart loses their job records and does
  not resume or replay those calls; durable schedules and chat delivery are
  separate mechanisms.
- **Runtime staging only caches assets.** It does not install, activate, restart,
  or qualify the runtime, and does not update IDE plugins.
- **The CLI is browser-first.** Running `refact` opens the dashboard instead of
  the retired TUI; `refact run` remains available for a headless chat turn.
- **Several implicit limits are retired.** Ordinary background agents no longer
  have lifetime step/effort caps, and shell and scheduled commands no longer gain
  implicit deadlines. Explicit timeouts and cancellation still apply. Legacy
  coordination admission keys `max_active_engine`, `max_active_project`,
  `max_active_root`, `max_pending`, and `max_outstanding` load but no longer limit
  admission and are omitted when settings are saved; provider and resource limits
  remain separate.
