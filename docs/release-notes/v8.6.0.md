# v8.6.0

v8.6.0 is a broad terminal, tooling, and reliability release: it adds a suite of TUI workflow surfaces, gives tool results a structured enrichment layer, exposes live performance diagnostics, expands provider and runtime configuration, and folds in the previously unreleased Windows, provider, and chat correctness work.

## Highlights

- **A fuller terminal workspace** — The TUI gains task-board, worktree, history, goal, browser, and activity surfaces, along with richer transcripts, code-intelligence cards, inline terminal images, and clearer approval details.
- **Structured tool results** — Native tools, browser and web tools, MCP integrations, file operations, search, diffs, and review can attach one bounded enrichment envelope, giving clients consistent references without scraping result text.
- **Live performance diagnostics** — A new Performance page shows aggregate chat, trajectory, indexing, watcher, and enrichment telemetry, with controls to enable, refresh, and reset bounded in-memory collection.
- **More reliable concurrent chats** — Queue progress no longer stalls under competing work, trajectory persistence moves off latency-sensitive paths, VecDB enqueueing is decoupled from saves, and watcher self-writes are suppressed.
- **Provider setup that follows the provider** — LiteLLM models can be discovered and enabled individually, quotas share one presentation, command-backed credentials are supported for user-level custom gateways, and OpenRouter has dedicated request settings.
- **Windows correctness** — Windows path matching, worktree registration, privacy zones, provider locks, and review paths now behave consistently with the rest of the engine.

## TUI

- Added dedicated task-board and worktree surfaces for inspecting cards, branches, base revisions, status, diffs, ahead/behind state, and worktree operations without leaving the terminal.
- Added a history surface for browsing saved conversations and their worktree metadata, plus a transcript overlay for navigating longer sessions.
- Goals now have a persistent dock and a detailed overlay, with controls for setting or updating a goal, changing its budget, and pausing, resuming, or stopping active work.
- Added browser and activity surfaces so page activity, screenshots, subagents, and other background work remain visible while an agent runs.
- Mode selection is grouped by purpose instead of presented as one flat list, making the relevant chat, agent, planner, and specialist modes easier to find.
- Transcript themes can be selected and previewed in place, with theme-aware syntax and UI styling.
- Code-intelligence results render as structured terminal cards rather than undifferentiated tool text.
- Supported terminals can render browser and chat images inline; a fallback action saves and opens the latest image externally when inline rendering is unavailable.
- Confirmation gates expose their rule and command details and let users inspect why approval is required before approving once, approving for the chat, or denying.
- The terminal surfaces retain compact fallbacks and explicit truncation markers on narrow screens instead of silently dropping content.

## Chat & Trajectories

- Fixed queue stalls under concurrent chat traffic so later input continues after active generation, cancellation, or approval handling completes.
- Cache-guard comparisons now use stable request snapshots, avoiding false prompt-prefix failures when a live request is changed elsewhere during generation.
- Removed image shrinking and omission recovery that rewrote existing history between retries and invalidated the prompt cache.
- Browser screenshot limits no longer mutate the persisted prompt prefix, preserving cache reuse in long browser-heavy chats.
- Trajectory writes use a detached writer cache and coordinated index updates, keeping serialization and filesystem work off the interactive chat path.
- VecDB indexing is queued independently after trajectory persistence, so a slow memory index does not hold up saving or the next turn.
- The trajectory watcher recognises engine-authored writes and suppresses their echo, avoiding redundant reload, indexing, and notification work.
- Subchats are written into per-conversation trajectory folders, keeping a run's child chats traceable to their parent.
- Failed subchat trajectories are persisted instead of discarded, and the cache guard no longer applies to non-interactive threads.
- Older chat history can be loaded incrementally, with cursor-aware pagination, retryable errors, and protection against overlapping page requests.
- Per-chat token controls now include a persisted auto-compression cap that can be adjusted or reset to the selected model's context maximum.
- Configurable chat and trajectory runtime settings expose persistence, index coordination, watcher suppression, tool-catalog snapshots, and VecDB path coalescing instead of requiring code-level changes.
- Dropped the provider-specific agent overlays and the `quick_agent` and `ultra_agent` modes, consolidating the mode set around the base agent workflow.
- Unknown or removed tools in a mode definition now produce a warning instead of failing silently.
- `escalate:{mode, justification}` on `shell` and `process_start` prompts only when the requested escalation actually widens enforced access, rather than forcing confirmation on every call.

## Tools & Enrichment

- Tool results can attach a versioned enrichment envelope containing bounded path, symbol, URL, citation, process, query, diff, artifact, diagnostic, agent, test, Git, and review references.
- Native diff and code-review results publish structured file and review references, allowing clients to link findings to their source instead of parsing prose.
- Browser, web, and MCP results use the same envelope for URLs, citations, artifacts, and affected resources, while retaining a plain-text fallback for older clients.
- File reads, directory trees, glob and regex searches, semantic search, and symbol lookup expose consistent file and query references.
- Workspace-path references are normalised, deduplicated, bounded, and privacy-redacted before they cross the API boundary; unsafe or non-workspace path metadata is discarded.
- The GUI and TUI consume the envelope in specialised cards while continuing to understand persisted legacy path metadata.

## Performance & Diagnostics

- Added a live Performance page with collection state, uptime, bounded sample counts, latency summaries, operation rates, and high-water marks for chat, trajectory, indexing, watcher, and enrichment work.
- Performance telemetry is aggregate-only, disabled by default, held in bounded memory, and can be enabled, refreshed, or reset from the interface.
- A bounded telemetry API exposes the same snapshot and collection controls without returning chat content or unbounded event histories.
- Reduced allocation churn in shared caches and file-watcher paths by reusing owned data and avoiding repeated large clones in frequently executed code.
- File indexing batches shared filesystem and query work instead of repeating metadata, path-correction, and database operations for every item.
- Path enrichment caches reusable scope and privacy decisions, removing repeated canonicalisation and policy checks from hot search and indexing paths.
- Trajectory lookup and history listing use indexed or bounded scans rather than repeatedly walking the complete conversation tree.
- Internal traces are excluded from trajectory indexing and VecDB enqueueing and are pruned to a bounded retained set, keeping long-running projects from accumulating diagnostic overhead.

## Providers & Settings

- Added native LiteLLM setup with dynamic model discovery from `/v1/models` and optional capability enrichment from `/v1/model/info`, so gateway aliases do not need hand-written model records.
- Discovered LiteLLM models are enabled by default and can be disabled individually; explicit opt-outs persist across rediscovery.
- LiteLLM aliases route to the appropriate chat or Responses endpoint, and prompt-caching metadata is handled without treating harmless gateway representation changes as cache corruption.
- Provider quotas are normalised into common usage windows, limits, reset times, plans, sources, and metadata, giving provider pages one consistent quota presentation.
- User-level custom and LiteLLM providers can obtain bearer credentials from a directly executed command, with a scrubbed environment, bounded output and timeout, in-memory caching, and one refresh-and-retry after an authentication rejection.
- OpenRouter settings support provider routing options and additional request-body fields while protecting core request fields from being overridden.
- Browser settings now cover the Chrome executable and launch arguments, headless mode, lifecycle timeouts, viewports, timing, and capture limits from one validated Settings page.
- Chat settings are capability-aware: controls and model defaults follow the selected model's supported reasoning, context, image, and tool-use capabilities instead of exposing options that cannot apply.
- Restored Google Antigravity OAuth and Cloud Code requests.
- Repaired xAI Grok subscription authentication and quota reporting.
- Suppressed false MCP OAuth expiry alerts.

## Privacy & Portability

- Path enrichment is portable across platform separators and equivalent path spellings, so structured references remain useful on Windows and Unix without leaking machine-specific forms.
- Privacy checks reuse compiled and cached path decisions, reducing policy overhead during large searches, indexing runs, and tool-result enrichment.
- Enrichment metadata has explicit redaction state and only accepts workspace-scoped paths for file, diff, and review references.
- Command-backed credential output stays in memory and is omitted from settings responses, persistence, and error messages.
- Worktree metadata now carries labels plus explicit base branch and base commit information, making diffs and merge targets stable when work starts from a non-default revision.
- Planner cards can override their base branch or commit; otherwise spawned worktrees inherit the planner chat's current branch and revision.

## Interface

- Home is now a unified workstream view, with Live edits hidden by default and the choice remembered.
- Settings pages share one visual language, a single right edge, and optimistic project-info updates.
- Added the Performance and Browser pages to the settings and navigation surfaces with consistent loading, empty, error, save, and reset states.
- Chat history loads older conversations on demand instead of limiting the interface to the first page.
- Mermaid flowcharts use the ELK layout engine for clearer spacing and routing, with theme-aware rendering and explicit zoom controls.
- Structured enrichment powers richer cards for execution, web, browser, file, search, diff, and review results while preserving raw output as a fallback.
- The chat scrollbar ends at the composer instead of running past it.
- Background agent cards are decluttered, and the workspace file-tree request no longer hangs without a timeout.
- Design-system updates align the box model, typography, motion, control heights, and weight tokens, including light-theme and narrow-viewport corrections.
- The daemon relaunches correctly after a self-update.

## Windows

- The `glob` tool matched nothing on Windows: candidate paths were only split on forward slashes, so a pattern like `*.rs` never reached a basename. Windows separators are now normalised before matching.
- Files inside a registered worktree were rejected with a permission error. The registry now validates and stores hashes from the same canonical path, including roots reached through 8.3 short names or symlinks.
- Privacy zone matching now considers canonical and supplied path spellings without retaining the unusable `\\?\` prefix, so equivalent Windows paths reach the same rule.
- Provider config and OAuth file locks wait for another handle instead of failing immediately, allowing concurrent token refreshes and settings saves to serialise safely.
- Code review paths are normalised consistently with the rest of the engine, so changed files can be found and linked correctly.
