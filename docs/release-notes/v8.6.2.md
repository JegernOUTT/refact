# v8.6.2

v8.6.2 turns the workspace file viewer into a real editor, removes two large sources of wasted work in provider listing and asset delivery, and stops background polling while the window is hidden.

## Highlights

- **The file viewer is an editor** — Files open in CodeMirror with syntax highlighting in both view and edit mode; double-click starts editing with the caret where you clicked, and Markdown renders as formatted text until you choose to see the source.
- **Listing providers is no longer expensive** — The bundled model catalog is parsed once instead of on every request, taking a provider listing from about 1.1 seconds of CPU to a few milliseconds.
- **Reloading the UI re-downloads almost nothing** — Assets are compressed and validated with an ETag, so a reload answers with 304s instead of resending roughly 20 MB.
- **A hidden window stops polling** — Status, ping, and interaction subscriptions pause while the tab or window is not visible.
- **A file-switching data-loss bug is fixed** — An unsaved draft could previously be written into a different file than the one it was edited in.
- **History shows your chats** — Internal traces and subagent conversations no longer appear as top-level history entries.

## Workspace

- The file viewer uses a single persistent CodeMirror editor whose read-only state is toggled in place, so entering and leaving edit mode keeps highlighting, scroll position, and the document itself.
- Double-clicking a file enters edit mode with the cursor at the clicked position rather than at the start of the document.
- Markdown files render through the standard Markdown view, including mermaid diagrams and SVG and HTML blocks, and can be switched to raw highlighted source by double-clicking or with a header toggle.
- The previous 50,000-character limit on syntax highlighting is gone; large files stay highlighted because the document is virtualized and language grammars load on demand.
- Added save with Mod+S, cancel with Esc, a two-step confirmation before discarding unsaved changes, and search across the whole document.

## Performance

- The bundled model catalog, a 3 MB snapshot covering 116 providers and 4,357 models, was re-parsed on every provider request and walked five times per parse. It is now parsed once and shared, and the six provider integrations that only borrowed it no longer copy it. A provider listing drops from about 1.03-1.15 seconds to 0.002-0.005 seconds.
- UI assets are served with gzip negotiation, a strong content hash as ETag, `If-None-Match` handling, and `Vary: Accept-Encoding`, so an unchanged asset answers 304 instead of resending its body. Streaming responses keep their unbuffered path.
- Polling accounted for 98 of 106 requests observed in a single session and continued while the window was hidden. Interaction, ping, and indexing-status subscriptions now pause when the document is not visible; intervals and state handling are otherwise unchanged.

## History

- Internal trace conversations and subagent conversations are filtered out of the history list and history tree, leaving the chats you started.
- Trajectory listing accepts a displayable-only filter so the engine returns just those conversations instead of the client discarding them after transfer.

## Fixes

- Editing one file, switching to another, and saving could write the first file's contents into the second under the second file's timestamp, passing the conflict check without warning. The viewer now resets per file.
- Live-edit highlighting for target and changed lines referenced a stale style scope and rendered invisibly.
- A test helper for intersection observers was constructed in a way that discarded its own methods, leaving it without an observe implementation.
- Scripted HTTP test servers now consume the request body before closing, so a client is no longer able to observe a connection reset instead of the response it was sent.
