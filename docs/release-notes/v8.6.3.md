# v8.6.3

v8.6.3 replaces the two overlapping background-agent tools with one `subagent` tool, gives agents a way to talk to each other and to you while they run, surfaces their work in a live panel and in real terminal tabs, rebuilds code review as a staged pipeline, consolidates the workspace behind one sidebar, and fixes a chain of browser, verifier, watcher, and idle-CPU problems found by auditing real usage.

## Highlights

- **One background tool: `subagent`** — `delegate` is removed. `subagent` always starts a stateful background child, inherits the parent's tools by default, can pick a model slot or a named model, and can take a goal, a plan, target files, and an isolated worktree that squash-merges on completion.
- **Subagent children now auto-approve edits and shell commands** — Children spawned through `subagent` run without confirmation prompts for editing tools and dangerous commands. This is a default change; see Behaviour changes.
- **Agents can coordinate** — `agents_overview`, `agent_message`, and `progress_report` let a parent inspect its agent tree, exchange messages and tracked questions with a child, and let a child publish its own status.
- **A live agents panel** — The chat shows the running agent tree with model, current tool, goal and plan state, worktree and merge status, questions, tokens, and cost, with navigation, messaging, and subtree cancellation.
- **Tool-run commands appear as terminal tabs** — Background `shell` and `process_start` commands run on a PTY and stream into interactive terminal tabs; non-TTY output is mirrored read-only.
- **An idle engine no longer burns CPU** — The workspace watcher stopped recursively watching `node_modules`, `target`, `.venv`, and `.git`; idle telemetry showed 155% CPU, 40,812 inotify watches, and roughly 22,900 inotify reads per second before the fix.
- **Chrome no longer leaks per turn** — A regenerated chat id made browser runtime lookup miss on every turn, launching a fresh Chrome and profile each time; a measured session reached 680 Chrome processes, 252 profile directories, and 77.7 GB RSS.
- **Task Planner cards can verify and merge again** — The verifier rejected any binary outside a six-entry allowlist and any command containing `$`, which first deadlocked merges and then let unverified cards merge under `force`.
- **Code review is a staged pipeline** — The review swarm is replaced by twelve configurable stages, each an agent with its own task, tool list, and wall-clock budget, run through a bounded pool. The pipeline itself checks each quoted evidence line against the file and the diff, merges duplicates, and reports facts separately from hypotheses. The `review` chat mode is gone; see Behaviour changes.
- **One sidebar behind an activity rail** — Files, Git, Agents, and Tasks live in a single dock opened from a 44px activity rail, with the in-dock switcher removed and the sidebar's open state, section, and width persisted per workspace.
- **Workspace file watching no longer deadlocks itself** — Dynamic watch registration called `watcher.watch()` from inside the notify callback, deadlocking the notify event loop and silently killing workspace file watching; registration now runs on the runtime.

## Behaviour changes

- The `delegate` tool is removed: the source, the registration, the `delegate_with_editing.yaml` subagent, and its entries in every default mode's `tools` and `tool_confirm` lists are gone. Use `subagent` instead. Stored `delegate` records still deserialize and still render, so existing conversations remain readable, and `delegate`/`delegate_with_editing` stay in the trajectory tool-preservation list so old chats keep their results through compression.
- **The `review` chat mode is removed.** `modes/review.yaml` is deleted, and the retired default is deleted from the global modes directory on next start when the file there is still the unmodified default. Review is a tool, not a mode: `review()` schedules and runs the stages itself, so there is no longer a mode to select in the UI or to name in a script or handoff. Anything that referred to a `review` mode has to call the tool instead.
- **The `ReviewReport` JSON changed shape.** A finding now carries `stage`, `reported_by`, `line_start`/`line_end`, `evidence_present`, `fix`, `locations`, and an optional `disputed{stage,reason}`; `category`, `confidence`, `rank_tier`, `verification_status`, `sources`, and `checks_performed` are gone, `evidence` is a single verbatim string rather than a list of evidence objects, and `impact`/`remediation` are replaced by `fix`. `ReviewSeverity::Critical` is now `Blocker` (the parser still accepts `critical` and `fatal` as input), and a `note` level was added below `low`. The report carries `depth`, `diff`, `stages`, `duration_ms`, `duplicates_merged`, and `scratch_dir`, and the old `checks_performed`, `summary`, `assumed_intent`, and `pipeline` blocks are gone. Anything consuming `review_report` from the tool metadata needs updating.
- The `review_commands` block in the engine global config is removed, along with the `review_evidence` execution source it fed. Review stages run commands through `shell` under the ordinary shell policy instead of an opt-in argv allowlist.
- `subagent.yaml` now sets `autonomous_no_confirm`, `auto_approve_editing_tools`, and `auto_approve_dangerous_commands` to true, so a child spawned with `subagent` edits files and runs shell commands without asking. Only `subagent.yaml` changed; every other subagent configuration still defaults to false, and an explicit `false` in a configuration is honoured.
- `subagent` no longer accepts `wait`, `max_steps`, or `notify_parent`. It is background-only; bound a child's work with `goal.budget.max_turns` instead. The per-child step ceiling is 60 and subagent nesting is capped at depth 5.
- `process_start` now defaults to a pseudo-terminal for background and service processes, and `shell` defaults to a PTY when `run_in_background` is true. Foreground `shell` commands still use pipes, and an explicit `tty` argument still wins. PTY size for tool-run processes is 120x32.
- **On Windows both tools default to pipes instead.** A Windows pseudoconsole does not deliver the child's output to the reader we hold, so a pty there produces a process whose output can never be read, and each one also brings up a console host — the same mechanism behind the blank `conhost.exe` window in #28. Windows therefore keeps the 8.6.2 pipe behaviour, the advertised `tty` default follows the platform, and an explicit `tty: true` is still honoured for anyone who wants to experiment. Linux and macOS are unaffected.
- `agent_cancel` cancels the whole subtree by default.
- The code-review result no longer carries the trailing JSON report or a per-agent coverage table in model-visible text; the structured report is attached to the tool result metering as `review_report`, with file references as `review_refs`.

## Subagents

- `subagent` takes `task`, `expected_result`, and optionally `target_files`, `tools`, `model_type`, `model_name`, `goal`, `plan`, `worktree`, and `auto_merge`. Omitting `tools` inherits the parent chat's tools; an explicit comma-separated list is validated against the registered tool catalog.
- Model resolution is `model_name`, then `model_type`, then the parent's model, and an unknown or unconfigured model is a hard error rather than a silent fallback. The six `model_type` slots are `default`, `light`, `thinking`, `buddy`, `model_2`, and `task_planner`.
- `goal` accepts a string or a `{content, criteria, budget}` object, and its budget caps the child's steps. `plan` installs a plan the child treats as ground truth. Both are seeded as hidden messages rather than mixed into the task text.
- `worktree: isolated` creates a worktree from the parent's scope base and, with `auto_merge` on by default, squash-merges on completion. The outcome is recorded as merged, conflict, skipped, or failed, and a nested isolated merge runs inside the parent worktree so conflicts are classified against the right base.
- Whatever tools are requested, `tasks_set`, `progress_report`, `agents_overview`, `agent_message`, and `validate_goal` are always available to a child.
- A child receives a snapshot of its active peers and a warning when its `target_files` overlap another agent's, both in its prompt and in the spawning tool's return value.
- Agent records carry model type, current tool, goal summary, plan presence, worktree id and branch, merge status, open questions, tokens used, and cost, all with legacy-safe defaults so older records still load.
- Cost reported for a child is the metered cost — provider metering when available, otherwise full-usage pricing. The previous estimate based on invented completion-token counts is gone, and cost is omitted rather than guessed when it is unknown.
- Live progress from a running child (step, tool started, tools finished, usage) updates its record, and sibling start and finish digests are delivered to peers.

## Agent interaction

- `agents_overview` renders the recursive agent tree — active agents plus those that finished within the last hour — with live introspection, and tells a child where it sits in the tree.
- `agent_message(to, text, expects_reply, reply_to)` sends to a child or descendant, or to `parent`. With `expects_reply` it creates a tracked question the parent answers by `reply_to` id. Messages are delivered into the child's context at step boundaries, and the inbox is drained before each model call.
- `progress_report` lets a child publish a concise status line that the parent and the panel can see.
- `agent_status`, `agent_list`, and `agent_result` render the full introspection, including tokens, cost, and open questions.
- Added `GET /v1/background-agents`, `POST /v1/background-agents/:id/cancel` with a `subtree` flag, and `POST /v1/background-agents/:id/message`.

## Performance

- The workspace watcher now builds a watch plan instead of recursively watching every root. Directories are classified as excluded, clean subtree (one recursive watch), or mixed (non-recursive plus descend), reusing the existing indexing blocklist; directories created at runtime under a non-recursive watch are registered from the event handler so coverage is not lost. Idle measurements before the change: 155% CPU, 15 MB/s reads, ~1.5 MB/s writes, 40,812 inotify watches, ~22,900 inotify reads per second, and a SQLite WAL pinned at 79.5 MB.
- `ChatSession::emit` returns early when the broadcast channel has no receivers, before the event sequence is incremented so clients do not see a gap and hard-reconnect. 92.5% of emitted events had no subscriber, costing about 1.8 GB of serialized JSON and leaving roughly 17 MB of unread event JSON per session in the 4096-slot ring.
- Trajectory saving drops the full-file read-back from the per-commit path in favour of a path-keyed metadata cache validated by file length and mtime, bounded at 256 entries; the detached writer's content-hash fingerprint uses the same stamp. Output stays pretty-printed.
- CodeGraph gained explicit WAL checkpointing: a passive checkpoint after each committed batch and a truncating one at a genuine idle boundary, with `wal_autocheckpoint` restored to SQLite's default of 1000 pages.
- The mutable tool pool is no longer rebuilt in full for each missing parallel slot; preparation sizes on the maximum per-tool deficit and concurrent misses are single-flighted. Tool instances are still owned and never shared between concurrent calls.
- `stream.first_delta` is split into `stream.prepare`, `token_count_request`, `request_send`, `provider_ttft`, and `first_content_delta`, because the original timer started before prompt preparation, tokenizing, RAG, privacy clearing, adapter JSON, and TLS and was never provider TTFT. `first_delta` itself is unchanged so it stays comparable across restarts.
- Dynamic watch registration called `watcher.watch()` from inside the notify callback, which deadlocks the notify event loop and silently kills workspace file watching; registration is now spawned onto the runtime. The knowledge watcher registers only the knowledge directories instead of watching the whole `.refact` directory or the whole project, and the trajectory watcher spawn is idempotent.
- Trajectory index maintenance is bounded: stale-entry removal is scoped to the owning directory, cached directories are LRU-evicted at 1024 entries, a failed write cleans up its temp file, and the save-mutex wait and metric scan are timed. Chat-to-root resolution is memoized and a parent is resolved with a single read.
- Dropped unfinished telemetry spans record `Cancelled` instead of vanishing, the misleading ops-per-commit rollup is replaced by reads-per-listing-call with per-caller counts, and `stream.prepare` gained size dimensions.
- The Anthropic `count_tokens` round trip moved off the pre-request path and is consumed only for usage attribution, the frozen-prefix checkpoint inside `stream.prepare` runs in the background, and request bodies are no longer re-serialized just to produce a log line.
- Integration loading is cached per config directory and catalog generation, and tool execution leases from the turn pool with the original rebuild kept as a fallback.
- Storage and retention are swept rather than accumulating: the background-agent registry prunes terminal records and coalesces progress writes, buddy memory-ops compaction runs on the write path behind a stamp-keyed parse cache, the stats endpoints scan newest-first with early stop and a fingerprint cache under a 180-day / 200 MiB retention bound, exec spill files are deleted with their record and capped and swept, and a daily task sweeps logs, browser profiles, the worktree registry, and stale CodeGraph stores.
- Source maps are excluded from the embedded assets, taking about 67 MB out of the binary, and the GUI build emits them hidden. On the GUI side memoized primitive selectors replace full-message-array subscriptions, the message index is incremental, generic tool output is capped head-and-tail with explicit expansion, and the remaining polls are visibility-gated.

## Trajectories

- A failed detached write no longer discards newer pending snapshots; the writer keeps draining with backoff and clears its error state on success.
- A watcher channel overflow schedules a recovery rescan instead of silently losing create, modify, and remove events.
- Callers that require durability are routed explicitly through a required-commit intent under the detached-writer rollout.
- A subagent's identity is restored from the durable agent registry whenever a context is built for a stateful child chat, on the spawn path, the command-queue path, and after a reload, so a child keeps its identity across restarts. `validate_goal` restores a missing child session from its trajectory.
- Terminal transitions clear the record's current tool while preserving its progress text.
- A durable save could hang forever. A required commit waited on the writer's notification, but the future was built while holding the state lock and only polled after releasing it, and only already-registered waiters get woken — so a write that failed fast, as it does for a symlinked trajectory path, a read-only mount, or bad permissions, recorded its error and notified before the waiter ever registered, and the caller waited forever. The waiter now arms the notification before dropping the lock, treats a writer that stopped with nothing in flight as terminal, and bounds the wait so any future stall reports a diagnosable error instead of hanging.
- Trajectory saves preserve `created_at`.
- A running subagent's conversation is mirrored into its registered chat session, so subscribing to that chat shows the messages the runner is committing rather than only the seed messages. Process-completion notifications no longer enqueue a regeneration on runner-owned subagent sessions, keeping a single trajectory writer.

## Browser

- Chat ids are now stable across turns; one-shot subchats keep the previous behaviour. Browser runtime ownership is stamped from that id, so the old per-turn regeneration made every lookup miss.
- Runtime lookup falls back from chat id to root chat id to background-agent id to a single unclaimed runtime, and never resolves when the choice is ambiguous. Removing a runtime kills Chrome and deletes its profile, a conservative sweep clears stale profiles, and `profile_lock_is_live` no longer reports dead pids as live from a stale `SingletonLock` symlink.
- Launch failures name the actual blocker instead of implying port exhaustion — the previous message claimed no ports were available between 8000 and 9000 while 953 of 1000 were free.
- Secrets are redacted by content across eval values, readouts, and assertion payloads, covering Slack, JWT, AWS, GitHub, Stripe, and npm token shapes. The previous allowlist matched only six WebAuthn key names, and a live session token had been persisted verbatim into trajectory JSON. Artifact paths are preserved.
- `tool_failed` is derived from the execution report's `ok` flag; previously it could never be true, so a failed batch looked identical to a successful one. Non-fatal steps still do not flip it.
- The tool schema publishes a per-action field manifest and drops properties no action accepts, so the flat property bag no longer advertises fields the deserializer rejects. HAR mode and content now have defaults, so `start_har_recording` works in one call.
- The design tools use the same runtime fallback, report actionable errors that name a concrete remedy, and discover design tokens instead of reading a hardcoded path. Their fail-closed guarantees are unchanged.
- A second wave of audit fixes makes batch semantics honest. Skipped steps are emitted as skipped results instead of vanishing, a `continue_on_error` envelope field runs later steps after a failure for independent probes, and a non-fatal outcome reports `ok: true` with no error plus the reason it did nothing. A mid-batch relaunch replays the last `navigate`, `open_tab`, or `set_content` and refuses to resume without page context, so a resumed screenshot can no longer capture `about:blank` and call it a success.
- `eval` awaits promises, fails the step on a thrown exception, serializes objects and arrays instead of collapsing them to null, and accepts `timeout_ms` (default 30000).
- Console levels from CDP are normalized so the page console counters can actually fire, and `tab_log` is served from the runtime console buffer with the tab-only path failing honestly instead of returning nothing.
- Network durations were microseconds labelled as milliseconds, so a 400 ms request read as 401978ms. `data:` and `blob:` URLs are collapsed and capped, a networkidle timeout lists the in-flight requests and the alternative waits, `wait_for_network_idle` reports under its own name, and "cdp session closed" joins the transport-dead markers.
- A navigation load-event timeout returns structured data — the load event, ready state, and how long it waited — and an unreadable `readyState` is a failure rather than a soft success.
- HAR recording no longer deduplicates after query-string redaction, which previously collapsed 40 distinct URLs into a single entry. Replay paths are contained per profile so the artifact from `stop_har_recording` is accepted by `route_from_har` on the next call, query redaction is idempotent, and owned runtimes keep their artifacts directory.
- A canceled download is a failure on the async path too and its cancel reason is preserved; a relaunch is gated on actually owning the browser process, and `connect()` no longer leaves an empty profile directory behind.
- Screenshots have one canonical artifact payload, persisted on disk with its path, so `image_region` can consume a chrome screenshot directly.
- Locator errors carry the locator description and a de-duplicated call log, strict-mode violations say how to narrow the match, main-world recreation bumps the frame generation, the page snapshot lists iframes, `dismiss_overlays` uses the real world manager, and locator polling tolerates transient resolution errors.
- Schema honesty: fieldless actions reject stray fields, `compose` and `width`/`height` are alternatives rather than silently overwritten, `block_service_workers` and `continue_on_error` are exposed, `click` and `hover` accept `timeout_ms`, unknown action names get edit-distance suggestions, `set_locale` applies `Accept-Language`, an injected WebSocket `close()` fires `onclose`, and pointer retries rotate scroll strategies.

## Code review

- `review` is now a staged pipeline instead of a swarm of review agents. Every stage is an agent that receives a task, a preferred tool list, a fallback instruction, and the review scope, and investigates with tools. The pipeline itself never reads compiler output and never judges a finding: it selects stages, runs them, fact-checks their output deterministically, merges duplicates, and renders the report.
- Twelve stages ship as YAML, one file per stage, in the new `review_stages` config kind: `mechanical`, `diff`, `impact`, `spec`, `security`, `dependencies`, `simplicity`, `concurrency`, `tests`, `execution`, `browser`, and `adversarial`, in that order. They are copied on first run to `~/.config/refact/review_stages/`, and a project can override any of them in `.refact/review_stages/<id>.yaml`. Each stage declares `phase`, `contract`, `depth`, `budget_minutes`, `writes_allowed`, `applies_when`, `preferred_tools`, `fallback`, and `task`.
- Stage selection is explicit and always reported: `depth: normal` runs the cheap stages, `deep` adds `tests`, `execution`, `browser`, and the adversarial pass, `concurrency` is opt-in, and an explicit `stages` list overrides depth with unknown names rejected against the catalog. Every stage that is not scheduled still gets a row saying why.
- Scope comes from arguments and git rather than from a model: the requested `files`, the diff from `base..HEAD` (base defaults to the merge-base with the upstream or main branch), and in `scope_mode: adjacent` one hop of reverse dependencies from `pr_blast`. Generated files, lockfiles, and snapshots are excluded.
- Findings are fact-checked deterministically. For each one the pipeline verifies that the quoted evidence really exists in the file within three lines of the stated range — relocating the finding when the quote is found elsewhere — and whether the range intersects a hunk of `base..HEAD`, falling back to `git blame` for moved code. Those two booleans, `evidence_present` and `introduced_by_diff`, are facts about the repository, not opinions about the finding.
- The report separates supported findings, which carry verified evidence or an executed reproduction, from hypotheses, which carry neither or were disputed. The adversarial pass can only set `disputed{stage,reason}`, which moves a finding into the hypotheses section; it cannot delete, edit, promote, or re-rank anything.
- Each stage reports coverage — files read, commands run with exit codes, tools it could not use, and whether it stopped early — and a status of `ok`, `timed out`, `failed`, or `not run`. A stage that hangs is `timed_out`, one that breaks the output contract is `failed` after exactly one repair turn, and stages that never started because the review deadline passed are `not_run`. A timed-out stage means that area was not reviewed.
- Duplicate findings on the same file with overlapping ranges or equivalent claims collapse into one, keeping every location in `locations` and every reporting stage in `reported_by`; the merged count is reported as `duplicates_merged`.
- New arguments: `base`, `plan`, `stages`, `parallel_depth`, `variants` (1-3 model variants per stage), `stage_budget_minutes`, `deadline_secs`, `browser`, and `browser_scenario`. The browser stage never runs without a scenario — `browser: true` requires `browser_scenario`, and supplying one schedules the stage at any depth.
- `scope_mode` (`strict`, `adjacent`, `broad`) now defaults to `strict` when `files` or `base` is given and `broad` otherwise, and scope expansion is still reported explicitly.
- Defaults live in the `review:` section of `review_agents.yaml`: `parallel_depth` 4, `variants` 1, `stage_budget_minutes` 6 (20 for stages that may write), `deadline_secs` 1800, `max_steps` 40, `max_files` 60, plus `model_slot`, `variant_slots`, and per-stage overrides under `stages:`.
- Each stage's raw answer and coverage is written to `.refact/review_scratch/<review-id>/<stage>.json`, which is gitignored, and the scratch directory is named in the report.
- Task Planner carries guidance on reading a review report: stage rows first, supported findings become fix cards, hypotheses get triaged rather than turned into cards, and `pre-existing` and `out of scope` markers are respected.
- `tools/dev/review_bench.sh` prepares a pinned oracle commit in a worktree and scores a saved report against `tools/dev/review_bench_oracle.json`, printing recall, reproduced share, false positives, per-stage status, and wall clock.
- The embedded stage catalog returned stages in embedding order while only the on-disk loader applied the canonical stage order, so a caller using the embedded catalog got a pipeline ordered by filename and `mechanical` no longer ran first. Both orderings now come from the same constant.
- A stage's `applies_when.path_globs` could never match a pattern with two wildcards: matching split on the first `*` and compared the remainder literally, so `**/migrations/*.sql` missed `db/migrations/001_init.sql`. Globs now compile through a real glob matcher with literal separators, and patterns without wildcards keep their plain suffix behaviour. No shipped stage declares `path_globs`, so this only affected the contract itself.
- `design_review` returns PASS, FAIL, or INCONCLUSIVE and cannot pass on zero evidence. `task_agent` states that review is planner-only, covered by a registry test asserting that every tool named in a mode prompt actually resolves.

## Task Planner

- The card verifier hard-rejected any binary outside a six-entry allowlist (`cargo`, `npm`, `npx`, `pytest`, `bun`, `yarn`), ignoring `.refact/shell_policy.yaml`, user allow rules, and YOLO mode, so dotnet, Go, make, and Gradle projects could never verify. That rejection was then classified as a genuine verification failure, so `merge_agent` refused even with `force=true`; because the gate runs before worktree cleanup, the worktree survived and `spawn_agent` refused to start any new card, pointing back at `merge_agent`. Verification now gates on the existing shell policy, where only deny rules such as `sudo` and `doas` block. Fixes #31.
- The old binary list survives only as a prose-scraping heuristic for bare markdown lines, guarded so acceptance-criteria prose like "make sure the tests pass" is not executed.
- Rejected and policy-denied outcomes are classified as infrastructure so `force=true` can bypass them; an actual command failure or a card with no commands still blocks.
- Verification commands that carry environment prefixes — for example `cd frontend && FOO=/abs/py PATH=/abs/tools:$PATH pnpm typecheck` — now run. The parser banned `$` outright, and after the fix above a rejection was force-bypassable, so such cards could merge without ever being verified. Leading `KEY=VALUE` tokens are parsed into an environment map threaded through the verifier and post-merge runners. The relaxation is narrow: `$NAME` expands only inside assignment values and only from the engine's own environment, argv tokens still reject `$` and every other shell character, `$(`, backticks, and newlines stay globally rejected, and `${NAME}`, `$1`, `$-`, and a bare `$` are errors. An all-assignments command is an error rather than an exec of nothing.
- Narrowed the prose-token list, which was dropping ordinary commands such as `make all`; the guard now skips assignment values, and a parse rejection is no longer reported as a command-filter rejection.
- `strip_sentence_period` stops eating the trailing dots in `go test ./...`.
- Both agent-spawn paths share one abandoned-worktree message naming the merge path and a merge-free discard path the verifier cannot block.

## Fixes

- The goal verifier read structured `CRITERION` status lines as gap bullets. It now separates them, synthesizes gaps from unmet criteria instead of returning inconclusive, and keeps prior behaviour for replies without `CRITERION` lines.
- LaTeX display `\[...\]` and inline `\(...\)` math rendered as a stray bracket plus raw source, because the math plugin only parses `$` and `$$`. Complete pairs are rewritten before rendering, skipping fenced and inline code and leaving unmatched delimiters alone so streaming output is never mangled.
- The scroll-to-bottom arrow, floating links, and queued-message container sat a full dock height away from the composer, because the composer clearance was applied both as a margin on the transcript area and again in their own offsets.
- A single subagent's token tick re-rendered every assistant row containing tool content, blinking the whole chat and jumping the scroll position. Cards now subscribe per agent, tool content and cards are memoized, agent updates are coalesced per agent id with status changes still flushing immediately, and the list is re-pinned to the bottom only when the reader is already there.
- Deleting a chat produced a recurring red error banner: the server's own "deleted" event triggered a second DELETE that 404d. Deletion is now applied locally on that event, a 404 counts as success, and in-flight deletes are deduplicated. Real failures still restore the chat and warn.
- The composer lagged and could crash on large drafts, because undo history kept a full string snapshot per keystroke. History is capped by entries and characters with at least one entry always kept, rapid end-appends are coalesced, autoresize runs in a cancelable animation frame with cached measurements instead of forcing a reflow per keystroke, and trigger scanning is bounded.
- Agent registry lifecycle hardening: descendant listing is cycle-safe, activity updates refresh the last-activity timestamp, terminal agents reject new inbox messages and retire their runtimes, the inbox is capped, merge-status transitions are validated, and terminal records ignore late activity and progress updates so a finished agent cannot appear to be working.
- A spawn notification could be emitted after the monitor had already broadcast completion; it is now emitted first. `mark_running`, `mark_waiting_for_approval`, and `mark_interrupted` are guarded on the first terminal transition.
- Agent lookup by child chat id uses a targeted registry query instead of cloning and scanning every record.
- Live agent updates fan out to both the parent and root sessions, and a child inherits its parent mode's tools rather than the global tool set.
- The GUI sends `chat_id` when cancelling or messaging an agent, and agent trees are scoped to the current chat.
- A process spawn event without a start timestamp is skipped instead of being reported with a missing field.
- On Windows, every process spawned with a PTY hung its caller. ConPTY only closes the output pipe once the pseudoconsole itself is closed, so the reader and the pty ended up owning each other: the pump held a registry clone, the registry entry owned the pty, and the read could only finish once the pty closed. Because shutdown waits for blocking tasks while cancelling the async work that would release the pty, a chat that ended before its process did could never finish. The pty reader now runs on a thread the engine owns, which shutdown does not await, so the drop chain completes and the read ends; the pseudoconsole is also released at the terminal transition before the pumps are drained, `ClosePseudoConsole` runs on its own thread because it can wait for the console host, and a resize afterwards reports a clear error.
- Concurrent background-agent registry writes failed with "Failed to rename: No such file or directory" whenever several agents were live: the two save paths both wrote through a fixed temp name, so the first rename moved the shared file away and the second found nothing, and coalesced progress writes made that overlap routine. Temp names now carry the pid and a counter, a failed write or rename cleans up after itself, and the error names both paths.

## Providers

- Added `claude-fable-5-1`. Anthropic gates newer models on the Claude Code client version, so every request failed with a message demanding client 2.1.251 or newer; the spoofed CLI identity is bumped to 2.1.258 and the billing fingerprint follows from it. The model is registered in both catalog snapshots with 1M context, 128k output, adaptive reasoning, tool use, vision, and published pricing — without a catalog entry it silently fell back to 200k context, a 4096-token output cap, and the legacy fixed thinking budget, which Fable 5.1 rejects outright because adaptive thinking is always on. Tests now assert the user agent embeds the version constant and that the version stays at or above the 2.1.251 floor.
- The six model slots can now be overridden per project. Overrides live in `<project>/.refact/model_defaults.yaml` on top of the global `providers.d/defaults.yaml`: a slot naming a model replaces the global one wholesale, and absent slots inherit. The merge happens at caps load, so chat, `subagent` `model_type`, the planner, buddy, review and `%MODELS_INFO%` all see the same resolution, and caps reload when the project file changes or the project root moves. The Models page gains a Global / This project scope switch with a per-slot override toggle that shows what is inherited.
